# Gallerate

> [!WARNING]
> **Поддержка проекта временно приостановлена.**
> Обещаний по поддержке нет: ответы на issues и релизы не гарантированы.
> Автор может продолжать работу над кодом, но новые функции и исправления
> не обещаны. Код выложен целиком и остаётся рабочим — форк и доработки
> приветствуются.
> Подробности и условия возобновления — в [SUPPORT.md](SUPPORT.md).

Разгреби галерею: каждый день приложение показывает сет фото из твоей галереи —
свайпаешь вправо (оставить) или влево (на удаление). Лучшие собираются на
отдельном экране, «плохие» ждут в разделе «Убрать», откуда их можно удалить с
устройства в один тап. Полностью офлайн, без аккаунтов и сети.

## Возможности

- Свайп-колода карточек с поворотом и пружинкой (в духе CardSlider)
- Подсказки «НРАВИТСЯ / НА УДАЛЕНИЕ» при перетаскивании
- Кнопки «оставить / удалить / пропустить», прогресс сета `3 / 10`
- **Отмена последней оценки**: ошибся свайпом — фото возвращается в колоду,
  а оценка снимается и фото снова считается непросмотренным
- **Дата снимка на карточке** — видно, свежее это фото или четырёхлетний
  кадр из отпуска, и решение принимается не вслепую
- **Сортировка по дате съёмки** в «Лучших» и в очереди уборки: от старых
  к новым. «Выкинуть старые кадры» — про возраст снимка, а не про дату
  оценки, поэтому дата съёмки сохраняется вместе с оценкой
- **Дата съёмки на плитке** — сортировка видна, а не заявлена
- **Предупреждение, если уведомления выключены** — иначе отказ в
  разрешении был незаметен, и напоминание просто не приходило
- **Тап по фото открывает его крупно** (щипковое масштабирование): по
  превью 1200 px размытость и лишний палец в углу не разглядеть
- Настраиваемый размер сета (5–50) и время появления; новый день — новый сет;
  можно проходить дополнительные сеты
- Случайные непросмотренные фото, без повторов уже оценённых
- Выбор альбомов/папок-источников (по умолчанию — вся галерея)
- Экран «Лучшие», экран «Убрать» с мультивыбором и удалением из галереи
- **Переоценка**: долгое нажатие по фото в «Лучших» или «Убрать» меняет
  оценку — ошибочный свайп можно исправить
- История по дням, статистика: график за 14 дней, баланс оценок, активные дни
- Светлая/тёмная/системная тема, локализация RU/EN
- Настройки: тема, язык, размер сета, время появления, выбор альбомов
- **Ежедневное напоминание** о новом сете в выбранное время
- Экспорт/импорт оценок в JSON через системный диалог файла,
  очистка оценок, полный сброс
- Если база недоступна — не вечный спиннер, а сообщение с кнопкой
  «повторить»

## Запуск

Нужен Flutter SDK 3.22+ (Dart 3.4+).

```powershell
cd gallerate
flutter pub get
flutter run
```

Папки платформ (`android/`, `ios/`) уже созданы в репозитории.

## Проверка

```powershell
flutter analyze                              # 0 ошибок, 0 предупреждений

flutter build apk --release --split-per-abi # APK по архитектурам
```

Тесты покрывают четыре слоя:

- `test/db_test.dart` — настоящий SQLite через `sqflite_common_ffi`
  (без устройства): переоценка не сбрасывает `sorted`/`deleted`,
  фильтрация удалённых, чанкование больших `IN`-запросов, импорт мусора,
  жизненный цикл наборов;
- `test/streak_test.dart` — серия дней, включая перевод на летнее время;
- `test/notifications_test.dart` — расписание напоминания: час остаётся
  20:00 в любой зоне (Минск, Берлин, Окленд, Лос-Анджелес) и через перевод
  времени, «сегодня или завтра», переходы через границы суток/месяца/года;
- `test/set_decision_test.dart` — правила «когда закрывать вчерашний набор,
  когда генерировать, что делать с пустым пулом, сколько недоступных
  ассетов пропустить»;
- `test/app_state_flow_test.dart` — сквозные сценарии `AppState` на
  настоящей БД и **фейковой галерее**: создание и закрытие сета, движение
  курсора, пропуск, клампинг оценки, защита от повторного тапа, переход на
  новый день, `clearRatings` и `resetAll`;
- `test/photo_manager_mock_test.dart` + `test/asset_image_test.dart` —
  проверка самого мока нативного канала и рендера миниатюр: неизвестный
  ассет не роняет экран, смена `assetId` перезапрашивает фото, повторные
  перестройки не плодят запросы (регрессия на бесконечный reload);
- `test/swipe_screen_test.dart`, `test/lists_screens_test.dart` —
  виджет-тесты всех экранов: свайп-цикл целиком (оценка чипом двигает
  курсор и ведёт счётчик, последняя оценка убирает колоду), «Лучшие» и
  «Убрать» с сетками фото, счётчики чипов, пустые состояния;
- `test/history_stats_test.dart` — «История» и «Статистика». Главное здесь
  не «экран нарисовался», а **сколько раз он ходит в базу**: на невидимой
  вкладке запросов нет вовсе, при открытии ровно один, повторный показ без
  изменений не перечитывает, новая оценка — перечитывает;
- `test/summary_screen_test.dart` — сводка по набору: пропуск не портит
  средний балл, неоценённое фото не считается пропуском, пустой набор не
  делит на ноль, а 50 ассетов читаются **одним** запросом;
- `test/root_shell_test.dart` — оболочка: пять вкладок, переключение,
  возврат на предыдущую вкладку без потери данных, реакция на возврат из
  фона (сет появляется без перезапуска приложения);
- `test/cleanup_delete_test.dart` — **удаление фото с устройства**, самый
  разрушительный сценарий: нижняя панель появляется только после выбора,
  удаление просит подтверждения, отмена ничего не трогает, а фото, которое
  система не смогла удалить, остаётся в очереди и не помечается удалённым.

### Экраны не грузят базу, пока их не открыли

Все пять экранов живут в `IndexedStack` и **строятся сразу при запуске
приложения**, когда выбрана только вкладка «Свайп». Если грузить данные в
`initState`, сводка по всем дням (`dayStats` + `recentRowsPerDay`) и вся
статистика считаются при каждом старте — для невидимых экранов. Поэтому
`HistoryScreen` и `StatsScreen` начинают с `Future? _future = null` и
загружают данные в `build`, когда `context.isTabVisible(...)` истинно и
данные ещё ни разу не запрашивались.

### Ловушка Dart в `setState` (найдена тестом, не чтением)

`setState(() => _future = f)` **возвращает Future**, потому что присваивание
в Dart само даёт значение. Flutter это прямо запрещает: падает assert
«setState() callback argument returned a Future» — в отложенном кадре, и в
стектрейсе указывает на место вызова, а не на строку с замыканием. Замена на
стрелку «починить» не помогает: `() => _future = f` ведёт себя так же.
Рабочий способ — сначала вычислить, потом присвоить в блочном замыкании:

```dart
final f = _load();
setState(() {
  _future = f;
});
```

Почему не поставлен текстовый гард на регексе: он соврал дважды. Первая
версия искала файлы по относительному пути и проходила, **не прочитав ни
одного файла**; вторая требовала вызова функции справа от `=` и потому
пропускала настоящую поломку `_future = f`, где `f` — переменная. Регекс не
может знать тип выражения, а проверка, которая «проходит» вхолостую, хуже
отсутствующей. Реальную защиту даёт поведенческий тест: с подсунутой поломкой
`test/history_stats_test.dart` падает, с исправленной — зелёный.

### Почему у экранов своя зависимость от хранилища

`sqflite_common_ffi` не работает внутри виджет-тестов Flutter: операции
БД не завершаются в fake-async зоне, и тест зависает намертво (проверено
минимальным примером — хватает одного `await AppDb.instance.totalSeen()`
внутри `testWidgets`). Поэтому SQLite проверяется обычными тестами
(`db_test.dart`, 33 штуки), а виджеты получают хранилище фейком через
явный параметр `store` — читать глобальный синглтон из виджета нельзя.

Побочный плюс: зависимость стала явной в сигнатуре экрана, а не спрятана
внутри `AppDb.instance`.

Тот же параметр есть и у `RootShell`: раньше оболочка создавала экраны
как `const` и они молча тянули глобальный синглтон, из-за чего **всё дерево
приложения** было непроверяемо — виджет-тест падал на
`databaseFactory is only initialized when using sqflite`. Теперь хранилище
доходит от корня до каждого экрана явно.
- `test/models_test.dart`, `test/card_deck_test.dart`,
  `test/rating_style_test.dart` — модель, жесты свайпа, дизайн-система;
- `test/settings_test.dart` — настройки против битых данных: приложение
  обязано запускаться, даже если в хранилище лежит невалидный JSON,
  число вместо списка или `daily_count = 500` из старой версии;
- `test/app_state_test.dart` — вычисления состояния (процент разобранной
  галереи, форматирование времени появления) без обращения к БД;
- `test/rating_chip_test.dart` — виджет-тесты чипов выбора оценки: рендер,
  порядок «от лучших к худшим», размеры, перенос на второй ряд, семантика
  для скринридера и **гарантия, что выбранный чип не обрезан** (регрессия
  на баг, найденный при запуске на эмуляторе).

Отдельно стоит отметить: `photo_manager` не мокается... — этот тезис больше
не верен, нативный канал подменяется (см. ниже).

**Нативный канал `photo_manager` тоже подменён.** Реальные ассеты создаёт
Android/iOS, поэтому в тестах канал `com.fluttercandies/photo_manager`
отдаёт синтетические данные в формате самого пакета
(`fetchEntityProperties` → `ConvertUtils.convertMapToAsset`). Благодаря
этому проверяются сетки фотографий и загрузка миниатюр. Миниатюры мок
намеренно не отдаёт: приложение обязано переживать их отсутствие
плейсхолдером, и это тоже проверяется.

Настройки читаются с защитой: `albumIds` разбирается через `try/catch`
с фильтрацией нестроковых элементов, `dailyCount` и `appearMinutes`
клампятся **при чтении**, а не только при записи, неизвестный код языка
игнорируется. Раньше битое значение в одном ключе роняло `init()` и
приложение открывалось белым экраном. Сам `init()` тоже не бросает
исключения: недоступное хранилище приводит к экрану запроса доступа,
а не к падению.

Интеграционные тесты БД уже окупились: они нашли баг, который не видели
тесты чистых функций — запрос серии фильтровал `rating != 0`, и день,
в который пользователь только промахивал, вообще не засчитывался.

`--split-per-abi` даёт три файла вместо одного: arm64-v8a — **19,4 МБ**,
armeabi-v7a — 17,0 МБ, x86_64 — 20,8 МБ (против 54,3 МБ universal).
Без этого флага Gradle конфликтует с `ndk.abiFilters`, который Flutter
проставляет самостоятельно.

### Что проверено на реальном Android

Прогон на эмуляторе Android 14 (API 34, x86_64), release APK:

- установка и запуск без падений, `Fully drawn`, ни одного FATAL в logcat;
- онбординг с чистой установки отрисовывается корректно;
- все пять вкладок открываются, нижняя навигация работает;
- «Лучшие» показывает реальные данные из SQLite: счётчики по оценкам
  (7→2, 8→1, 9→1) и бейдж «10 new»;
- `pickUnseen` действительно находит фото — сет создаётся (0/10);
- процесс приложения ни разу не попал в ANR.

Найдено при этом и исправлено: чип выбранной оценки в «Лучших» рисовался
обрезанным (горизонтальный `ListView` с `reverse: true` уводил выбранный
элемент за границу viewport) — заменён на `Wrap`.

Ограничение проверки: эмулятор без аппаратного ускорения давал постоянные
ANR системных процессов (`systemui`, `wellbeing`, `contacts`), из-за чего
сценарии с длительным нажатием и удалением фото довести до конца не удалось.
Логика этих сценариев покрыта тестами и кодом, но на «живом» устройстве их
стоит повторить.

### Известные ограничения

- Напоминание ставится в режиме `inexactAllowWhileIdle`: система может
  доставить его с задержкой в несколько минут. Это осознанно — точные
  будильники требуют `SCHEDULE_EXACT_ALARM`, который на Android 13+
  выдаётся пользователю вручную.
- «Разложить в галерее» копирует фото в альбомы `Gallerate 1..10`,
  поэтому в галерее появляются дубликаты. Оригиналы остаются на месте.
- Уведомления требуют разрешения `POST_NOTIFICATIONS` (Android 13+),
  его запрашивают в конце онбординга.

## Права доступа

### Android (`android/app/src/main/AndroidManifest.xml`)

Добавить внутрь `<manifest>`:

```xml
<uses-permission android:name="android.permission.READ_MEDIA_IMAGES" />
<uses-permission android:name="android.permission.READ_MEDIA_VIDEO" />
<uses-permission android:name="android.permission.READ_MEDIA_VISUAL_USER_SELECTED" />
<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE"
    android:maxSdkVersion="32" />
<uses-permission android:name="android.permission.ACCESS_MEDIA_LOCATION" />
```

Удаление фото на Android 10+ идёт через системный диалог подтверждения
(`MediaStore.createDeleteRequest`) — дополнительного права не нужно.

### iOS (`ios/Runner/Info.plist`)

```xml
<key>NSPhotoLibraryUsageDescription</key>
<string>Gallerate показывает фото из вашей галереи для оценки. Данные не покидают устройство.</string>
<key>NSPhotoLibraryAddUsageDescription</key>
<string>Сохранение изменений в библиотеке.</string>
```

На iOS удаление каждого батча подтверждается системным диалогом PhotoKit.

## Как это работает

1. При первом запуске — онбординг: доступ к галерее, размер сета, время,
   альбомы, разрешение на напоминания.
2. В настроенное время сет генерируется сам (локальное уведомление), при
   возврате в приложение или по кнопке «Открыть сейчас».
3. Каждое решение пишется в SQLite (`photos.rating`: 1..10 / 0=пропуск),
   курсор сета двигается, возврат к карточке невозможен.
4. По завершении — сводка: лайки/дизлайки/пропуски, всего оценено, процент
   разобранной галереи.
5. Раздел «Убрать» удаляет отмеченные фото через `photo_manager.editor`.
   Долгое нажатие по фото в «Лучших» или «Убрать» меняет оценку.

### Сознательные технические решения

- **Серия дней считается через `DateTime(y, m, d - 1)`, а не через
  `subtract(Duration(days: 1))`.** В сутках бывает 23 или 25 часов (перевод
  времени), и вычитание Duration от полуночи даёт 23:00 предыдущего дня —
  сравнение перестаёт работать, и серия обнулялась дважды в год.
- **Альбомы при выборе «вся галерея» не суммируются.** Они пересекаются
  («Все фото» ⊃ «Камера»); при сложении процент «галерея разобрана» завышался
  в разы. Берётся альбом с `isAll`, а при отборе сетa — дедупликация по id.
- **Ассеты сканируются по всему альбому, а не по первым 3000.** Старый потолок
  делал 7000 фото больших альбомов недостижимыми навсегда.
- **Переоценка не сбрасывает флаг `sorted`** (используется UPDATE, а не
  REPLACE), иначе разложенные в галерею фото попадали бы в сортировку
  повторно и давали дубликаты.
- **Напоминание ставится в режиме `inexactAllowWhileIdle`** — без
  `SCHEDULE_EXACT_ALARM`, который на Android 13+ требует ручного разрешения.
- **Локальная часовая зона задаётся явно.** Пакет `timezone` отдаёт
  `tz.local == UTC` по умолчанию (это написано в его исходниках), поэтому
  напоминание на «20:00» срабатывало бы в 20:00 UTC — на три часа позже в
  Минске. Зона берётся через `flutter_timezone` до планирования.
- **Окно карточек собирается синхронно из кэша** с упреждающей догрузкой.
  Раньше на каждый сдвиг курсора создавался новый `Future`, и колода
  проваливалась в спиннер после каждого свайпа.
- **Пустой пул запоминается на сутки** — иначе минутный таймер пересканировал
  бы всю библиотеку каждый раз, когда новых фото не осталось.
- **Правила работы с сетом вынесены в чистые функции** (`data/set_decision.dart`)
  и покрыты тестами: когда закрывать вчерашний набор, когда генерировать, что
  делать с пустым пулом.
- **Невидимые вкладки не перечитывают БД.** `IndexedStack` держит все пять
  экранов живыми, поэтому без проверки видимости каждая оценка порождала бы
  четыре лишних запроса в SQLite.
- **Повторный тап по одной карточке игнорируется.** Пока пишется оценка в
  SQLite, вторая попытка перетирала бы первую, а курсор сдвигался бы один раз.
- **Серия пересчитывается в конце сета даже без единой оценки:** день, в который
  пользователь только промахивал, тоже считается активным.
- **`totalSeen` считает `deleted = 0`.** Иначе после удаления половины
  оценённых фото процент «галерея разобрана» завышался вдвое.

## Дорожная карта

Сделано и работает: локальные уведомления к времени появления сета, системные
альбомы для «Лучших» (копирование фото в `DCIM/Gallerate <оценка>`), темная
и системная темы, RU/EN, экспорт и импорт оценок.

Что можно делать дальше — по убыванию пользы:

- **Отмена удаления** — сейчас удалённое из «Убрать» уходит безвозвратно.
  На Android 11+ файлы попадают в корзину системы, и можно было бы
  предлагать «вернуть последние N удалённых» прямо из приложения;
- **Экспорт «Лучших» одним архивом** — сейчас экспортируются только оценки,
  а сами файлы остаются на устройстве;
- **Больше языков** — структура l10n готова к расширению;
- **Настольная версия** — приложение полностью офлайновое, поэтому
  работать с галереей на большом экране удобнее.
